# 展会展品入馆封箱与撤展核对系统

参展商与场馆方共用的展品全流程核对系统：从**逐件清单 → 按箱入馆 → 展位占位 → 撤展核实 → 放行出馆**全程留痕，缺件可追溯到**最后经手人**。

## 一键启动

```bash
./start.sh
```

首次运行会自动安装前端依赖、构建 Svelte 前端并启动后端。打开 http://localhost:3000 ，右上角选择操作身份即可演示。

- 后端：Rust + Axum + SQLx（SQLite，数据库文件 `data/app.db`）
- 前端：Svelte + Vite（构建产物由后端托管；开发时可 `cd web && npm run dev` 走 5173 端口代理）
- 现场照片：保存到本地 `uploads/`，经 `/uploads/<文件>` 访问
- 闸口扫码：`POST /api/gate/scan` 为模拟接口

## 角色与演示账号

| 账号 | 角色 | 能做什么 |
|---|---|---|
| 王入口 | receiver 入口接收员 | 按箱接收、关联箱内展品 |
| 李场馆 | staff 场馆人员 | 占位/转移/撤展核实/审批异常/确认变更/开具放行凭证 |
| 赵主管 | manager 场馆主管 | 同场馆人员 |
| 陈展商 / 林展商 | exhibitor 参展商 | 提交清单、上报异常、发起变更申请（**无权**审批异常/确认变更/开具凭证） |

认证为演示用的 `X-User-Id` 请求头，前端右上角切换身份即自动携带。

## 核心流程

1. **清单**：参展商提交逐件清单（每展商一份，提交后不可直接改）。
2. **收箱**：入口人员创建箱号并勾选箱内展品封箱入馆；任一展品校验失败整箱回滚。
3. **占位**：布展后把展品登记到展位；数据库部分唯一索引保证**同一件展品同一时刻只在一个展位**。
4. **撤展核实**：按原清单逐件核对实物，无误标记「已核实出馆」。
5. **放行**：场馆方开具放行凭证——整单放行要求入馆数 = 已核实 + 已出馆 + 缺件结案且无未处理异常；部分放行必须对应已确认的「提前撤展」变更。
6. **闸口**：扫码核销凭证，展品标记出馆；凭证只能核销一次。

## 变更与异常

- **临时替换展品 / 转借展位 / 提前撤展**：走变更申请，场馆方确认后才生效；系统只追加新记录，**入馆记录只增不改**。
- **缺件 / 破损**：必须上传现场照片；**参展商无权批准异常放行**，只能由场馆人员/主管审批。批准缺件 → 展品「缺件结案」；批准破损 → 按破损核实出馆。
- 存在未处理异常时不能开具放行凭证。

## 数量核对与追溯

- `GET /api/exhibitors/{id}/reconciliation`：入馆 / 在场 / 已核实 / 已出馆 / 缺件结案 / 未处理异常与 `balanced` 判定。
- `GET /api/items/{id}`：展品当前展位、入馆箱号、异常记录与完整流转时间线，最后一条事件的经手人即**最后经手人**。
- 看板页（首页）实时展示各展位展品与各展商数量核对结果。

## 主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/manifests` | 参展商提交逐件清单 |
| POST | `/api/boxes` | 按箱接收（箱号 + 展品关联） |
| POST | `/api/placements` | 展位占位（重复占位返回 409） |
| POST | `/api/transfers` | 展位间转移（追加记录） |
| POST | `/api/teardown/verify` | 撤展逐件核实 |
| POST | `/api/exceptions` | 上报缺件/破损（multipart，照片必传） |
| POST | `/api/exceptions/{id}/decide` | 审批异常（参展商 403） |
| POST | `/api/amendments` | 变更申请（替换/转借/提前撤展） |
| POST | `/api/amendments/{id}/decide` | 确认/驳回变更（参展商 403） |
| POST | `/api/exit-passes` | 开具放行凭证（参展商 403） |
| POST | `/api/gate/scan` | 闸口扫码核销（模拟） |
| GET | `/api/board` | 展位看板数据 |
| GET | `/api/items/{id}` | 展品详情与流转记录 |
